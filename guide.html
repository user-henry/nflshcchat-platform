接入指南

面向开发者：把「使用 NFLSHC 账号登录」接入到你的项目。所有示例代码均可一键复制， 只替换 client_id / client_secret / 回调地址即可跑通。

① 授权流程（Authorization Code Flow）

NFLSHC 开放平台使用标准授权码模式：授权码 5 分钟有效且只能用一次，访问令牌 2 小时有效，刷新令牌 30 天有效。

┌──────────┐     ① 跳转授权页      ┌────────────────────────────┐
│ 开发者应用 │ ───────────────────▶ │ accounts.nflshcchat.cc.cd  │
│ (你的网站) │                      │  用户登录 → 查看权限 → 同意 │
└──────────┘                      └────────────────────────────┘
      ▲                                         │
      │ ③ 回跳 ?code=xxx&state=yyy               │ ② 用户同意
      └─────────────────────────────────────────┘
      │
      │ ④ 服务端 POST /api/oauth/token（code + client_secret）
      ▼
┌──────────────────────────┐   ⑤ GET /api/oauth/userinfo (Bearer access_token)
│ worker.nflshcchat.cc.cd  │ ◀───────────────────────────────────
└──────────────────────────┘
1
把用户引导到授权中心
拼接授权地址并跳转，redirect_uri 必须与登记值完全一致，state 用于防 CSRF，回跳时会原样返回：
授权地址模板 
https://accounts.nflshcchat.cc.cd/authorize.html
  ?client_id=nac_xxxxxxxx
  &redirect_uri=https://你的站点/callback
  &scope=profile email
  &state=随机防CSRF字符串
2
用户同意后回跳
成功：https://你的站点/callback?code=naco_xxxxxxxx&state=…
用户拒绝：…?error=access_denied&error_description=用户拒绝了授权&state=…
请务必校验 state 与发起时一致，否则直接拒绝该次回调。
3
服务端用 code 换取令牌
POST https://worker.nflshcchat.cc.cd/api/oauth/token，body 为 { grant_type, code, client_id, client_secret, redirect_uri }； 返回 access_token / refresh_token / expires_in / scope。 此步骤必须在服务端完成，client_secret 绝不可出现在前端。
4
读取用户信息
GET /api/oauth/userinfo，Header 携带 Authorization: Bearer <access_token>。 只会返回你申请并且用户同意的 scope 范围内的字段，密码与密码哈希永远不会返回。
5
刷新 / 吊销令牌
刷新：POST /api/oauth/token + { grant_type: "refresh_token", refresh_token, client_id, client_secret }
吊销：POST /api/oauth/revoke + { client_id, client_secret, token }； 用户在 accounts.nflshcchat.cc.cd/apps.html 撤销授权后，相关令牌立即失效。

② 在 platform 配置应用

开发者平台（本站点）用于创建与管理你的 OAuth 应用。

  1. 用你的 nflshcchat 账号登录 开发者登录页（密码在浏览器内做 SHA-256 哈希后再提交）。
  2. 进入 应用管理，点击「创建应用」，填写应用名称、简介、主页与图标。
  3. 登记回调地址（每行一个，需 http/https 开头）：授权回跳时地址必须与登记值完全一致，否则返回 invalid_redirect_uri。
  4. 勾选需要的权限范围（scope），用户会在授权页逐项看到并可拒绝敏感权限。
  5. 创建成功后立即保存 client_secret——它只显示这一次，服务端只存哈希，关闭弹窗后无法再查看，只能重置。
  6. 把 client_id 与 client_secret 写入你服务端的环境变量 / 配置文件，然后按下面的示例代码接入。
  7. 在 应用详情 页可以随时编辑信息、重置密钥（旧密钥立即失效）、查看授权用户与提交全站封禁申请。
💡
调试阶段建议先只申请 profile，跑通后再按需增加 email / messages 等敏感权限，用户更容易点「同意」。

④ 示例代码（一键复制）

示例与平台 API 契约完全一致。把 nac_你的应用ID、nacs_你的密钥、https://你的站点/callback 替换成你在平台里登记的真实值即可运行。

⚠️
示例中的 state=xyz 只是占位，正式项目请生成随机值并在回调时校验，防止 CSRF 攻击。
Node.js / Express 
const express = require('express');
const app = express();

const CLIENT_ID = 'nac_你的应用ID';
const CLIENT_SECRET = 'nacs_你的密钥';
const REDIRECT_URI = 'https://你的站点/callback';
const API = 'https://worker.nflshcchat.cc.cd';
const ACCOUNTS = 'https://accounts.nflshcchat.cc.cd';

// ① 跳转授权中心
app.get('/login', (req, res) => {
  const state = Math.random().toString(36).slice(2);
  req.session = req.session || {};
  res.redirect(`${ACCOUNTS}/authorize.html` +
    `?client_id=${CLIENT_ID}&redirect_uri=${encodeURIComponent(REDIRECT_URI)}` +
    `&scope=${encodeURIComponent('profile email')}&state=${state}`);
});

// ② 回调：换令牌 + 读用户信息
app.get('/callback', async (req, res) => {
  const { code } = req.query;
  const tokenRes = await fetch(`${API}/api/oauth/token`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      grant_type: 'authorization_code', code,
      client_id: CLIENT_ID, client_secret: CLIENT_SECRET, redirect_uri: REDIRECT_URI
    })
  });
  const tokens = await tokenRes.json();
  const infoRes = await fetch(`${API}/api/oauth/userinfo`, {
    headers: { Authorization: 'Bearer ' + tokens.access_token }
  });
  const user = await infoRes.json();
  res.send(`欢迎，${user.nickname || user.username}！`);
});

// ③ 校验用户是否被你在项目内封禁
async function checkBan(username) {
  const r = await fetch(`${API}/api/oauth/check`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ client_id: CLIENT_ID, client_secret: CLIENT_SECRET, username })
  });
  return r.json(); // { granted, banned, reason }
}

app.listen(3000);
Python / Flask 
import requests
from flask import Flask, redirect, request

app = Flask(__name__)
CLIENT_ID = 'nac_你的应用ID'
CLIENT_SECRET = 'nacs_你的密钥'
REDIRECT_URI = 'https://你的站点/callback'
API = 'https://worker.nflshcchat.cc.cd'
ACCOUNTS = 'https://accounts.nflshcchat.cc.cd'

@app.route('/login')
def login():
    # ① 跳转授权中心
    return redirect(f'{ACCOUNTS}/authorize.html?client_id={CLIENT_ID}'
                    f'&redirect_uri={REDIRECT_URI}&scope=profile%20email&state=xyz')

@app.route('/callback')
def callback():
    code = request.args.get('code')
    # ② 换令牌
    tokens = requests.post(f'{API}/api/oauth/token', json={
        'grant_type': 'authorization_code', 'code': code,
        'client_id': CLIENT_ID, 'client_secret': CLIENT_SECRET,
        'redirect_uri': REDIRECT_URI,
    }).json()
    # ③ 读用户信息
    user = requests.get(f'{API}/api/oauth/userinfo',
                        headers={'Authorization': f"Bearer {tokens['access_token']}"}).json()
    return f"欢迎，{user.get('nickname') or user.get('username')}！"

# ④ 校验项目内封禁
def is_banned(username: str) -> bool:
    r = requests.post(f'{API}/api/oauth/check', json={
        'client_id': CLIENT_ID, 'client_secret': CLIENT_SECRET, 'username': username,
    }).json()
    return bool(r.get('banned'))
PHP 
<?php
const CLIENT_ID     = 'nac_你的应用ID';
const CLIENT_SECRET = 'nacs_你的密钥';
const REDIRECT_URI  = 'https://你的站点/callback';
const API           = 'https://worker.nflshcchat.cc.cd';

// ① 跳转授权中心
if (isset($_GET['login'])) {
    header('Location: https://accounts.nflshcchat.cc.cd/authorize.html?client_id=' . CLIENT_ID
        . '&redirect_uri=' . urlencode(REDIRECT_URI) . '&scope=' . urlencode('profile email') . '&state=xyz');
    exit;
}

// ② 回调换令牌
if (isset($_GET['code'])) {
    $ch = curl_init(API . '/api/oauth/token');
    curl_setopt_array($ch, [
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_POST => true,
        CURLOPT_HTTPHEADER => ['Content-Type: application/json'],
        CURLOPT_POSTFIELDS => json_encode([
            'grant_type' => 'authorization_code',
            'code' => $_GET['code'],
            'client_id' => CLIENT_ID,
            'client_secret' => CLIENT_SECRET,
            'redirect_uri' => REDIRECT_URI,
        ]),
    ]);
    $tokens = json_decode(curl_exec($ch), true);

    // ③ 读取用户信息
    $ch2 = curl_init(API . '/api/oauth/userinfo');
    curl_setopt_array($ch2, [
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_HTTPHEADER => ['Authorization: Bearer ' . $tokens['access_token']],
    ]);
    $user = json_decode(curl_exec($ch2), true);
    echo '欢迎，' . ($user['nickname'] ?? $user['username']);
    exit;
}

⑤ 校验端口：查询用户在你项目内的状态

服务端到服务端接口，用 client_secret 鉴权（不需要用户令牌），建议在用户每次调用你项目的高风险接口前调用一次。

请求 
POST https://worker.nflshcchat.cc.cd/api/oauth/check
Content-Type: application/json

{
  "client_id": "nac_xxx",
  "client_secret": "nacs_xxx",
  "username": "someone"
}
响应 
{
  "ok": true,
  "username": "someone",
  "granted": true,
  "banned": false,
  "reason": "",
  "bannedAt": null
}
  • granted：该用户是否授权过你的应用（是否在你的管辖范围内）。
  • banned：是否被你在项目内封禁；为 true 时 reason 是封禁原因。
  • 业务建议：granted=false 时提示用户重新授权；banned=true 时拒绝服务并展示原因。
curl 快速验证 
curl -X POST https://worker.nflshcchat.cc.cd/api/oauth/check \
  -H "Content-Type: application/json" \
  -d '{"client_id":"nac_xxx","client_secret":"nacs_xxx","username":"someone"}'
🛡️
项目内封禁仅在你自己的项目内生效：它只写入你的应用管辖范围，用户在主站不受影响。 若需要全站封禁，请在应用详情页提交申请并附详细理由，由主站管理员 huangzhiyuan 审核批准后执行。

⑥ 错误码

接口返回 { "error": "…", "error_description": "…" }，请按错误码给出准确提示。

error含义排查建议
invalid_clientclient_id / client_secret 不正确或应用被停用到应用详情页重置密钥并更新服务端配置
invalid_grantcode / refresh_token 无效、过期或已使用授权码 5 分钟有效且只能用一次，重新走授权流程
invalid_redirect_uri回调地址未登记与平台登记值做逐字符比对（含结尾斜杠、http/https）
invalid_scope未选择有效权限在创建/编辑应用时至少勾选一个 scope
access_denied用户拒绝授权，或用户已撤销授权提示用户重新授权
invalid_token访问令牌无效或已过期用 refresh_token 刷新，或重新授权
login_required需要先登录 nflshcchat 账号把用户引导到授权中心登录
client_suspended应用已被管理员停用联系主站管理员处理

⑦ 安全建议

  • 开发者看不到密码：任何接口都不返回 password / password_hash。
  • 开发者不能操作主站账号：项目内封禁只写入 oauth_project_bans，不影响用户在主站的状态；只有主站管理员能封禁/冻结主站账号。
  • 敏感信息需用户明确授权：email、messages 等敏感 scope 在授权页会高亮提示。
  • 用户可随时撤销：用户在 accounts.nflshcchat.cc.cd/apps.html 撤销授权后，相关令牌立即失效，你的服务端应处理 invalid_token。
  • 回调地址白名单：redirect_uri 必须与登记值完全一致，防止授权码被劫持。
  • 密钥保管：client_secret 只在创建/重置时返回一次；如疑似泄露请在平台立即重置。
  • 全站封禁需人类审核：开发者的封禁申请必须附带理由，由主站管理员核定后执行。
